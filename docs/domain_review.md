# Domain review and optional collaboration packages

**Pending:** no domain expert has validated this prototype and no contributor endorsement is claimed. This file contains no proposed collaborator names or personal information.

The first review should decide whether the question is worth studying before increasing case count or adding an LLM. Ask:

1. Which research-record transformation is realistic, useful and separable from clinical advice?
2. Who may issue a correction, and which provenance facts are observable to the agent?
3. When should a later source override an earlier one, and when should both remain in conflict?
4. Is preserving the reported quantity/unit pair sufficient, or is a validated conversion task necessary?
5. What is the correct output when a correction removes a value without supplying a replacement?
6. Which action boundaries distinguish drafting from publication or source editing?
7. Which ordinary benign workflow would the proposed control over-block?
8. Which existing benchmark task already tests the same thing?

Possible opt-in work packages are workflow and annotation review, measurement/unit provenance, rehabilitation-research documentation realism, or evaluation engineering. Each package should have a short agreed time budget and a concrete deliverable that the person wants to own. Expertise is a reason to invite a review, not evidence of willingness to participate.

Discuss credit and authorship based on actual contributions and obtain agreement before naming any author. Initial review can remain a bounded consultation without a continuing project commitment. Do not import real records or private conversations to make the benchmark feel more realistic. Any future data collection or system integration needs its own permissions and research review.
